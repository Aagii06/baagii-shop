# GOLDEN UVS Admin

GOLDEN UVS дэлгүүрийн удирдлагын хэсэг. Дэлгүүртэй (`../web`) ижил backend
(`../backend`, admin-ийн API нь `/api`) ашигладаг Next.js 16 апп. Хуучин
eshop-service-ийн хаяг `.env`-д коммент хэлбэрээр үлдсэн. Ажруг admin-ы бүтэц дээр суурилсан,
харин өнгө, лого, фонт нь дэлгүүрийн брэндийнх (`src/app/globals.css`).

## Эхлүүлэх

```bash
cp .env.example .env   # API хаягаа шалгана
npm install
npm run dev            # http://localhost:3771
```

Нэвтрэх нэр (ж: `admin`), нууц үгээр `POST /auth/login`-оор нэвтэрнэ
(`{ userName, password }`, `src/lib/api/auth.ts`). Хадгалсан token-ийг апп
нээгдэхэд `GET /auth/getUserData`-аар шалгана; `user` буцаахгүй (зочны)
token-той бол дахин нэвтрүүлнэ.

## Хуудсууд

Зөвхөн утсанд зориулсан: том дэлгэц дээр ч утасны өргөнтэй багана болж харагдана.
Дээд талд брэнд + профайл цэс (Хүргэлтийн тэмдэглэл, Гарах), доор 4 табтай цэс.

| Зам                | Агуулга                                                     | Backend |
| ------------------ | ----------------------------------------------------------- | ------- |
| `/login`           | Нэвтрэх                                                     | `POST /auth/login` |
| `/`                | Самбар: захиалга/борлуулалтын тоо, график, нөөц дуусч буй бараа, сүүлийн захиалга | `GET /product`, `GET /order`, `GET /order/sales?range=` |
| `/products`        | Барааны жагсаалт — хайлт, үндсэн категориор шүүх           | `GET /product`, `GET /category/tree` |
| `/products/[id]`   | Бараа засах                                                 | `GET /product/{id}`; хадгалах: `PUT /product/{id}`; устгах: `DELETE /product/{id}` |
| `/products/new`    | Бараа нэмэх                                                 | хадгалах: `POST /product`; шинэ зураг: `POST /file/upload` |
| `…/variants`       | Категорийн сонголтууд (өнгө, хэмжээ, …) болон хослол бүрийн тоо, үнэ (`/products/new/variants`, `/products/[id]/variants`) — барааны формтой хамт хадгалагдана | `GET /product` (`variants[].attr`) |
| `/orders`          | Захиалга — төлөвөөр шүүх, батлах/буцаах                     | `GET /order`, `PUT /order/{id}/status` |
| `/orders/[id]`     | Захиалгын дэлгэрэнгүй, төлөвийн явц, бараа буцаах           | `GET /order/{id}`, `POST /order/{id}/return` |
| `/orders/new`      | Худалдан авагчийн өмнөөс захиалга                           | `POST /order` |
| `/partner-requests` | Хамтран ажиллах хүсэлт — батлах, татгалзах, дугаараар нэмэх | `GET /partnerRequest`, `POST /partnerRequest/{id}/approve` · `/reject`, `POST /partnerRequest` |
| `/categories`      | Категорийн жагсаалт (3 хүртэл түвшин) — сонголтууд, засах, дэд категори нэмэх, устгах | `GET /category/tree` (үзүүлэлтийн нэр `attrs`-аас); устгах: `DELETE /category/{id}` |
| `/categories/new`, `/categories/[id]` | Категори нэмэх/засах: нэр, барааны сонголт. "Нэмэх" нь үндсэн категори, мөрийн `+` (`?parentId=`) нь дэд категори үүсгэнэ; эцэг категори формд харагдахгүй, солигдохгүй | `GET /category/tree`, `GET /attr`; хадгалах: `POST /category`, `PUT /category/{id}` (сонголт `attrIds`-аар) |
| `/attrs`           | Үзүүлэлт (attr) — өнгө, хэмжээ гэх мэт, утгуудтай нь; засах, устгах | `GET /attr`, `DELETE /attr/{id}` |
| `/attrs/new`, `/attrs/[id]` | Үзүүлэлт нэмэх/засах: нэр, утгууд (дараалал); код, өнгө формд байхгүй — засахад байсан утгаараа буцаж илгээгдэнэ | `GET /attr/{id}`; хадгалах: `POST /attr`, `PUT /attr/{id}` (`attrValues`: `id`-тай нь засагдана, `id`-гүй нь шинээр үүснэ) |
| `/delivery-notes`  | Хүргэлтийн тэмдэглэлүүд                                     | `GET /doNote` |

## Барааны сонголт (өнгө, хэмжээ, …)

Хамгийн сүүлийн түвшний (дэд категоригүй) категори бүр бараа нь юугаар
ялгаатайг (`Category.attrs`) хадгална; дэд категоритой категорид сонголт
байхгүй. Бараа
бүртгэхэд тухайн категорийн сонголт бүрт сонгох хэсэг гарч, хослол бүрд
(ж: Хар · 42) тоо, үнэ оруулна.

- Сонголтууд (attr) болон тэдгээрийн утгууд (attrValue) өгөгдлийн сангаас
  `getAttrs()`-аар (`src/lib/api/attrs.ts`, `GET /attr`, хуудаслан бүгдийг)
  ирнэ: Өнгө, Хувцасны хэмжээ тоо/үсэг, Гутлын хэмжээ тоо/нас, Багтаамж гэх
  мэт. Категори нь сонголтуудаа `attrIds`-аар хадгална (`POST /category`,
  `PUT /category/{id}`, backend өөрөө CategoryAttr руу sync хийнэ), дээд тал
  нь 3. `/category/tree`-ийн node бүр `attrs: { id, name }[]` буцаана — категорийн жагсаалт нэрийг эндээс авч `/attr` дууддаггүй.
- `viewType: "image"` сонголт (өнгө) өнгөний дугуй, утга бүрийн зурагтай;
  backend-д ийм талбар байхгүй тул нэр нь "өнгө" агуулсан эсвэл утга нь
  `color`-той attr-ийг ингэж харуулна;
  `"text"` нь энгийн chip. Бараан дээр каталогид байхгүй утгыг гараар нэмж
  болно (`attrValueId: null`).
- `attrs: []` — сонголтгүй, бараа нэг хувилбартай, зөвхөн тоо ширхэг
  оруулна.
- Зураг: "Ерөнхий" (`post.images`, өнгө сонгоогүй үед дэлгүүрт харагдана) ба
  өнгө бүрийн (`postAttrValues[].image` + `images`, эхнийх нь нүүр) гэж
  табаар тусдаа оруулна. Шинэ зураг хадгалах хүртэл `blob:` URL-аар
  урьдчилан харагдаж, `PostInput.newFiles`-ээр дамжина.
- Хадгалахад `newFiles`-ийг эхлээд `POST /file/upload`-оор хуулж, `blob:`
  URL-уудыг буцаасан файлын id-аар солино; утга бүрийн зураг `attrs`-аар
  хадгалагдана (`src/lib/api/posts.ts`).

## Анхаарах зүйл

- Захиалга үүсэхэд барааны үлдэгдэл хасагдаж, буцаалтад (мөрөөр эсвэл
  `returned` төлөвөөр) буцаж нэмэгдэнэ — backend тооцно.
- Хамтран ажиллах хүсэлт батлахад тухайн дугаараар SHOPPER хэрэглэгч үүснэ.
  Нууц үггүй тул тэр хэрэглэгч одоохондоо admin-д нэвтэрч чадахгүй.
- Token нь `localStorage`-д хадгалагдах тул жинхэнэ хамгаалалт нь backend
  (`../backend/middleware/auth.js`).
