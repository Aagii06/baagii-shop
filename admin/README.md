# GOLDEN UVS Admin

GOLDEN UVS дэлгүүрийн удирдлагын хэсэг. Дэлгүүртэй (`../web`) ижил eshop-service
backend-ийг ашигладаг Next.js 16 апп. Ажруг admin-ы бүтэц дээр суурилсан,
харин өнгө, лого, фонт нь дэлгүүрийн брэндийнх (`src/app/globals.css`).

## Эхлүүлэх

```bash
cp .env.example .env   # API хаягаа шалгана
npm install
npm run dev            # http://localhost:3771
```

Нэвтрэх нэр (ж: `admin`), нууц үгээр `POST /auth/login`-оор нэвтэрнэ
(`{ userName, password }`, `src/lib/api/auth.ts`). Хадгалсан token-ийг апп
нээгдэхэд `GET /auth/getUserData`-аар шалгана; `user` буцаахгүй (зочны)
token-той бол дахин нэвтрүүлнэ.

## Хуудсууд

Зөвхөн утсанд зориулсан: том дэлгэц дээр ч утасны өргөнтэй багана болж харагдана.
Дээд талд брэнд + профайл цэс (Хүргэлтийн тэмдэглэл, Гарах), доор 4 табтай цэс.

| Зам                | Агуулга                                                     | Backend |
| ------------------ | ----------------------------------------------------------- | ------- |
| `/login`           | Нэвтрэх                                                     | `POST /auth/login` |
| `/`                | Самбар: захиалга/борлуулалтын тоо, график, нөөц дуусч буй бараа, сүүлийн захиалга | Нөөц: `GET /post`; бусад нь **жишээ өгөгдөл** |
| `/products`        | Барааны жагсаалт — хайлт, үндсэн категориор шүүх           | `GET /post`, `GET /category/tree` |
| `/products/[id]`   | Бараа засах                                                 | `GET /post/{id}`; хадгалах/устгах **endpoint алга** |
| `/products/new`    | Бараа нэмэх                                                 | хадгалах **endpoint алга** |
| `…/variants`       | Категорийн сонголтууд (өнгө, хэмжээ, …) болон хослол бүрийн тоо, үнэ (`/products/new/variants`, `/products/[id]/variants`) — барааны формтой хамт хадгалагдана | `GET /post/{id}` (`postAttrs`, `postProducts`) |
| `/orders`          | Захиалга — төлөвөөр шүүх, батлах/буцаах                     | **жишээ өгөгдөл** |
| `/orders/[id]`     | Захиалгын дэлгэрэнгүй, төлөвийн явц                         | **жишээ өгөгдөл** |
| `/categories`      | Категорийн жагсаалт (3 хүртэл түвшин) — сонголтууд, засах, дэд категори нэмэх, устгах | `GET /category/tree` (`attrIds`-тай), `GET /attr`; устгах: `DELETE /category/{id}` |
| `/categories/new`, `/categories/[id]` | Категори нэмэх/засах: нэр, барааны сонголт. "Нэмэх" нь үндсэн категори, мөрийн `+` (`?parentId=`) нь дэд категори үүсгэнэ; эцэг категори формд харагдахгүй, солигдохгүй | `GET /category/tree` (`attrIds`-тай), `GET /attr`; хадгалах: `POST /category`, `PUT /category/{id}` (сонголт `attrIds`-аар) |
| `/delivery-notes`  | Хүргэлтийн тэмдэглэлүүд                                     | `GET /doNote` |

## Барааны сонголт (өнгө, хэмжээ, …)

Хамгийн сүүлийн түвшний (дэд категоригүй) категори бүр бараа нь юугаар
ялгаатайг (`Category.attrs`) хадгална; дэд категоритой категорид сонголт
байхгүй. Бараа
бүртгэхэд тухайн категорийн сонголт бүрт сонгох хэсэг гарч, хослол бүрд
(ж: Хар · 42) тоо, үнэ оруулна.

- Сонголтууд (attr) болон тэдгээрийн утгууд (attrValue) өгөгдлийн сангаас
  `getAttrs()`-аар (`src/lib/api/attrs.ts`, `GET /attr`, хуудаслан бүгдийг)
  ирнэ: Өнгө, Хувцасны хэмжээ тоо/үсэг, Гутлын хэмжээ тоо/нас, Багтаамж гэх
  мэт. Категори нь сонголтуудаа `attrIds`-аар хадгална (`POST /category`,
  `PUT /category/{id}`, backend өөрөө CategoryAttr руу sync хийнэ), дээд тал
  нь 3. `/category/tree`-ийн node бүр `attrIds`-аа буцаана.
- `viewType: "image"` сонголт (өнгө) өнгөний дугуй, утга бүрийн зурагтай;
  backend-д ийм талбар байхгүй тул нэр нь "өнгө" агуулсан эсвэл утга нь
  `color`-той attr-ийг ингэж харуулна;
  `"text"` нь энгийн chip. Бараан дээр каталогид байхгүй утгыг гараар нэмж
  болно (`attrValueId: null`).
- `attrs: []` — сонголтгүй, бараа нэг хувилбартай, зөвхөн тоо ширхэг
  оруулна.
- Зураг: "Ерөнхий" (`post.images`, өнгө сонгоогүй үед дэлгүүрт харагдана) ба
  өнгө бүрийн (`postAttrValues[].image` + `images`, эхнийх нь нүүр) гэж
  табаар тусдаа оруулна. Шинэ зураг хадгалах хүртэл `blob:` URL-аар
  урьдчилан харагдаж, `PostInput.newFiles`-ээр дамжина.
- Backend-д хэрэгтэй:
  - барааг хадгалахдаа `PostInput.attrs` / `variants` / `images`-ийг
    (`src/lib/api/posts.ts`) хүлээж авах, `newFiles`-ийг файл сервис рүү хуулах.

## Анхаарах зүйл

- eshop-service одоогоор зөвхөн **унших** endpoint-уудтай. Хадгалах, устгах,
  захиалгын төлөв солих товчнууд `src/lib/api/`-ийн stub функцийг дуудаж
  "endpoint байхгүй" гэсэн мэдэгдэл харуулна (`endpointMissing`). Endpoint
  нэмэгдмэгц тэр функцийн биеийг л солиход хуудсууд шууд ажиллана.
- Захиалга, борлуулалтын өгөгдөл `src/lib/api/sample.ts`-ээс ирдэг бөгөөд
  тэдгээр хуудсан дээр "жишээ өгөгдөл" гэсэн тэмдэглэгээ гарна. Жинхэнэ API
  холбогдмогц `src/lib/api/orders.ts`-ийн функцуудыг солиод `sample.ts`-ийг
  устгана.
- Нэвтэрсэн хэрэглэгч admin эрхтэй эсэхийг апп шалгахгүй; admin эрхийн
  шалгалтыг backend талд хийх шаардлагатай.
- Token нь `localStorage`-д хадгалагдах тул хамгаалалт client талд явагдана;
  жинхэнэ хамгаалалт нь backend-ийн `checkAuth`.
